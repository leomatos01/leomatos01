🚨 O problema

Reprovação e desistência

Disciplinas introdutórias de programação registram taxas de reprovação que frequentemente ultrapassam 30–50%.

Falta de base lógica

O aluno enfrenta sintaxe + lógica + resolução de problemas ao mesmo tempo, sem preparo prévio.

Feedback tardio

No modelo tradicional, o erro só é descoberto dias depois, na correção da prova.

Ritmos diferentes

Turmas heterogêneas deixam alunos com dificuldade para trás, sem acompanhamento individual.

Contexto: o pensamento computacional é habilidade prevista na BNCC — o problema começa antes da faculdade.

💡 A solução: LogicaMente

🗺️ Trilha progressiva

4 módulos: Pensamento Computacional → Algoritmos e Variáveis → Condicionais → Laços de Repetição.

✏️ Prática com correção automática

24 exercícios em 3 formatos: múltipla escolha, V/F e ordenação de blocos de código (Parsons problems).

💬 Feedback imediato

Dica ao errar, explicação ao acertar — o erro vira aprendizado na hora.

🏅 Gamificação

XP, 5 medalhas, sequência de dias de estudo e ranking da turma.

📊 Painel do professor

Relatórios de progresso e identificação de alunos que precisam de reforço.

🌐 100% web e gratuita

Roda em qualquer navegador, sem instalação — inclusive em laboratórios de escolas públicas.

📋 Requisitos que guiaram o desenvolvimento

Funcionais (principais)

  • Trilha com desbloqueio progressivo (RF03)
  • Exercícios interativos + correção automática (RF05/RF06)
  • Feedback com dicas graduais (RF07)
  • XP, medalhas e ranking (RF08/RF09)
  • Relatórios para o professor (RF11)

Não funcionais

  • Web e responsivo (RNF01)
  • Interface para iniciantes (RNF02)
  • Disponível 24/7, custo zero (RNF05)

Regras de negócio

  • RN01: nota ≥ 70% desbloqueia o próximo módulo
  • RN02: pontuação máxima só na 1ª tentativa
  • RN03: ranking restrito à turma

⚙️ Processo de desenvolvimento

  1. 1Análise: definição do problema, justificativa (BNCC, evasão) e levantamento de requisitos;
  2. 2Projeto: desenho da trilha pedagógica, das regras de negócio e da arquitetura;
  3. 3Implementação: desenvolvimento iterativo — conteúdo pedagógico primeiro, depois a lógica, depois o visual;
  4. 4Testes: validação automatizada do conteúdo e testes funcionais de cada requisito;
  5. 5Publicação: versionamento no GitHub e deploy no GitHub Pages.

A cada nova ideia, a pergunta-filtro: "isso atende a qual requisito?"

🏗️ Arquitetura e diferenciais técnicos

Stack

  • HTML5 + CSS3 + JavaScript puro — sem frameworks, sem build, carregamento instantâneo;
  • localStorage — progresso persistido no navegador;
  • GitHub Pages — hospedagem gratuita e disponível 24/7.

Decisão-chave

Aplicação 100% estática: toda a lógica (correção, XP, desbloqueio) roda no cliente. Sem servidor e sem banco de dados = custo zero e nenhum ponto de falha.

Separação clara

data.js (conteúdo pedagógico) separado de app.js (lógica) — adicionar um módulo novo não exige mexer na lógica.

📈 Métricas de sucesso

1Usuários ativos/mês

Meta: 100 no 1º semestre · Google Analytics

2Conclusão de módulos

Meta: ≥ 60% no módulo 1; ≥ 30% no curso completo

3Acerto na 1ª tentativa

Meta: entre 60% e 80% (eficácia pedagógica)

4Retenção em 7 dias

Meta: ≥ 40% retornam na semana seguinte

5Satisfação (NPS)

Meta: NPS ≥ 50 · formulário ao concluir módulo

Juntas cobrem o ciclo completo: chegar → usar → aprender → voltar → recomendar.
